# 中国宏观脉搏

这是一个用于查看已审核中国宏观周报和月报的静态页面。数据更新由开发会话完成核验后写入；网站本身不会在线抓取或解析报告。

## 让 Codex 或 Claude Code 继续开发

在新的开发会话中，先发送下面这段提示词：

```text
请先完整阅读 HANDS_OFF.md、SESSION_SAMMARY.md 和 WINDOWS_DEVELOPMENT.md，检查当前仓库状态并遵守其中的数据可信度、验证和部署约束。完成检查后，概述当前状态，再处理我的下一项需求。
```

这些交接文档面向开发代理，记录当前约束、已作决定和 Windows 开发注意事项；它们能帮助新的会话安全地接续工作。

## 添加一份新的周报或月报

准备好报告类型、原文链接或完整粘贴内容；如已知，也请提供发布日期。还请说明是否有内部审核限制，例如可使用的来源范围、署名、版权或发布限制。

然后将以下提示词和资料一起发送给开发代理：

```text
请先完整阅读 HANDS_OFF.md、SESSION_SAMMARY.md 和 WINDOWS_DEVELOPMENT.md。下面是新的【周报/月报】原文链接或内容：<粘贴链接或正文>。请在当前开发会话中完成读取、解析、口径与日期核验，再更新静态数据文件；不要在网站中增加运行时抓取或解析功能。完成后运行 npm run verify，并告诉我如何查看本地效果和部署结果。
```

这里的架构约束是：报告读取和解析只发生在开发代理的当前开发会话中，绝不发生在运行中的网站里；“会话”不是报告日期字段。开发代理还会分别核对报告发布时间、报告覆盖期、观测期或观测截止日，以及比较期或比较基准，再将经审核的数据更新到静态文件。

## 本地查看效果（Windows PowerShell）

在项目目录打开 PowerShell 后运行：

```powershell
npm ci
npm run dev
```

在浏览器中打开 Vite 在终端打印的 `Local` 地址。

## 查看 GitHub Pages 效果

在仓库页面打开 **Deployments** 查看当前发布及其页面链接；也可以进入 **Actions → Deploy to GitHub Pages** 查看发布进度和结果。这样即使仓库转移给新的所有者，操作入口也无需改变。

当前发布使用仓库 Pages 设置中的自定义域名，构建资源路径以网站根目录为基准。若同事转移仓库、移除自定义域名或改回 GitHub 默认项目地址，请让开发代理先同步检查 Pages 设置、构建配置和预览方式，不要只修改其中一处。

## Agent 交接文档

需要交接或继续维护时，请让开发代理阅读：

- [HANDS_OFF.md](HANDS_OFF.md)：当前工作约束与完成标准。
- [SESSION_SAMMARY.md](SESSION_SAMMARY.md)：已作决定、背景和待处理事项。
- [WINDOWS_DEVELOPMENT.md](WINDOWS_DEVELOPMENT.md)：Windows PowerShell 的开发和排查说明。

页面内容仅应使用经审核允许的研究资料；发布前请按内部流程确认版权、免责声明、署名、引用精度与原文链接。
